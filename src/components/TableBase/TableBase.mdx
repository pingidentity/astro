# TableBase

Data tables display information in a grid-like format of rows and columns.
They organize information in a way that's easy to scan so that users can look for patterns and develop insights from data.

Column header names describe the type of content displayed in each column.
Each row contains data related to a single entity.

TableBase should:
- Have consistently aligned content.
- Use multiple heading rows for higher-level grouping of the columns.
- Use column dividers sparingly.

This basic component is rendered as an HTML `<table>`, which accepts the `<TBody>` component and the `<THead>` as children.

### When to Use

Use TableBase when you need a fully custom table implementation that goes beyond what higher-level table components provide. Common use cases include:

- Sticky columns (e.g., pinning the last column during horizontal scroll)
- Custom row or column grouping
- Non-standard selection behaviors
- Bespoke cell rendering or layout that requires direct control over the table structure

TableBase is the lowest-level table primitive in Astro and gives you direct access to the underlying React Aria/Stately table hooks. Use it when you need that level of control.

### Required Components

This component requires these additional components:

- **TableCaption** — renders an accessible `<caption>` element for the table
- **THead** — wraps the header section (`<thead>`)
  - **Column** — defines each column header cell (`<th>`)
- **TBody** — wraps the body section (`<tbody>`)
  - **Row** — defines each data row (`<tr>`)
    - **Cell** — defines each data cell (`<td>`)

### Styling state classes

TableBase applies state classes to the row (`<tr>`), cell (`<td>`), and column header (`<th>`) elements so custom CSS or theme overrides can target specific states:

| Class | Meaning |
| ----- | ------- |
| `is-selected` | The row is selected (selection mode is enabled). Applied to rows. |
| `is-hovered` | The pointer is over the row. Applied to rows. |
| `is-pressed` | The row is being pressed. Applied to rows. |
| `is-disabled` | The row is disabled. Applied to rows. |
| `is-focused` | The element has keyboard focus. Kept for backward compatibility; prefer `is-focus-visible` for new styles. Applied to rows, cells, column headers, and the column resizer. |
| `is-focus-visible` | The element has keyboard focus. Applied to rows, cells, column headers, and the column resizer. |
| `is-active-row` | The row was activated by mouse or touch. Applied to rows only when `onRowAction` is provided. |

Notes:

- `is-focused` and `is-focus-visible` are emitted only for keyboard focus — Tab into the table, arrow-key navigation, or focusing the column resizer. Mouse and touch interaction applies neither class, so styling away a click indicator cannot accidentally remove the keyboard focus ring.
- `is-active-row` has no default styling. Use it to add a click indicator (such as a border or background) without affecting the keyboard focus ring. Pressing Enter on a focused row applies it as well, since the row was activated.
- Focus classes are element-local: a row or cell gets `is-focused` / `is-focus-visible` only when that element itself receives keyboard focus, not when an interactive control inside a cell (such as an input or checkbox) is focused. The control shows its own focus indicator.
